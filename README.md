# RAMO Gift Card

کارت هدیه‌ی رمزارزی روی شبکه‌ی BNB Chain (USDT / USDC) با ۳۲ طرح (از جمله ۷ طرح تصویری تولد و ۵ طرح تصویری عاشقانه). رابط کاربری و پیام‌های تلگرام به فارسی، عربی، انگلیسی، اسپانیایی و چینی در دسترس‌اند؛ متن کارت فونت، اندازه و چرخش قابل تنظیم دارد و نوشته‌های چاپی را می‌توان جابه‌جا کرد و رنگ هرکدام را تغییر داد. خریدار با کیف پول خودش پرداخت می‌کند؛
کارت و کیف هدیه در تلگرام برای خریدار ارسال می‌شود و او می‌تواند آن را برای گیرنده بفرستد.

## امنیت (اصل پروژه: ما هیچ کلیدی نگه نمی‌داریم)
- کیف هدیه **در مرورگر خریدار** ساخته می‌شود. ۱۲ کلمه فقط هنگام ارسال برای چند ثانیه در حافظه‌ی Worker است تا به تلگرام خریدار برسد؛ در KV، لاگ یا هیچ‌جای دیگر نوشته نمی‌شود.
- هیچ خزانه‌ی پولی و کلید خصوصی‌ای روی سرور نیست. پرداخت‌ها مستقیم از کیف فرستنده به کیف هدیه و به **آدرس کارمزد** می‌رود و Worker آن‌ها را روی زنجیره بررسی می‌کند (حداقل ۳ تایید).
- پرداخت به حساب تلگرام خریدار بسته است: کارمزد شامل یک کد سفارش کوچک است که فقط برای همان خریدار ثبت شده؛ پس کسی نمی‌تواند تراکنش دیگران را برای سفارش خودش استفاده کند.
- تا وقتی هدیه به تلگرام خریدار تحویل نشده، ۱۲ کلمه فقط در مرورگر خودش نگه داشته می‌شود تا با بستن صفحه پولی گم نشود. بعد از تحویل پاک می‌شود.

## ساختار
- `api/worker.js`: Cloudflare Worker (یک فایل، بدون وابستگی). تست: `cd api && npm test`
- `site/`: سایت React (موبایل‌پسند، در Mini App تلگرام هم کار می‌کند)

## راه‌اندازی Worker
1. Cloudflare → Workers & Pages → Worker به نام `ramo-giftcard-api` → Edit code → محتوای `api/worker.js` را بگذارید → Deploy.
2. Settings → Bindings → KV namespace: نام `GIFT_KV`، namespace همان که ساخته‌اید.
3. Settings → Variables and secrets:
   - Secret `BOT_TOKEN`: توکن بات `@ramofinance_alerts_bot`
   - Variable `FEE_ADDRESS`: آدرس BNB Chain **کیف خودتان** برای دریافت کارمزد (حتماً کیفی که کلیدش دست شماست)
   - Variable `ADMIN_USERNAMES`: username مدیران با کاما، مثلاً `@admin_one,@partner_two`؛ شناسه‌ی عددی لازم نیست.
   - Secret `TELEGRAM_WEBHOOK_SECRET`: یک مقدار محرمانه‌ی تصادفی برای اعتبارسنجی webhook تلگرام.
   - اختیاری: `ALLOWED_ORIGINS`, `FEE_USD` (پیش‌فرض 0.5), `MIN_GIFT`, `MAX_GIFT`
4. webhook بات را به Worker وصل کنید (مقدارهای محرمانه را جایگزین کنید):
   ```sh
   curl -X POST "https://api.telegram.org/bot${BOT_TOKEN}/setWebhook" \
     --data-urlencode "url=https://<worker-domain>/api/telegram/webhook" \
     --data-urlencode "secret_token=${TELEGRAM_WEBHOOK_SECRET}"
   ```
   هر مدیر باید یک‌بار گفت‌وگوی خصوصی بات را باز کند و `/start` بزند؛ Worker username را با فهرست بالا تطبیق می‌دهد و chat را خودش ثبت می‌کند. مدیر لازم نیست ID عددی را پیدا یا وارد کند. تلگرام برای هر بات فقط یک webhook فعال دارد؛ اگر بات را سرویس دیگری استفاده می‌کند، webhook را با آن سرویس ادغام کنید.
5. خریدار هم باید پیش از پرداخت یک‌بار بات را باز کند و Start بزند تا تلگرام اجازه‌ی پیام خصوصی بدهد؛ گیرنده‌ی هدیه نیازی به بات یا شناسه‌ی تلگرام ندارد.
6. قبل از راه‌اندازی عمومی آدرس قرارداد USDT و USDC را در BscScan دوباره چک کنید (بالای `worker.js`).

## راه‌اندازی سایت
1. GitHub → Settings → Pages → Source: **GitHub Actions**. با هر push روی `main` سایت منتشر می‌شود:
   `https://ramofinance.github.io/ramo-giftcard/`
2. BotFather → `/setdomain` → بات را انتخاب کنید و `ramofinance.github.io` را بدهید (برای دکمه‌ی ورود با تلگرام).

## توسعه و build محلی
از ریشه‌ی مخزن برای اجرای نسخه‌ی توسعه:
```sh
cd site
npm install
npm run dev
```
برای build سازگار با GitHub Pages:
```sh
cd site
VITE_BASE_PATH=/ramo-giftcard/ npm run build
```
اجرای آزمون‌های Worker:
```sh
cd api
npm test
```

## مراحل بعدی
1. سایت کامل (همین نسخه) ← تست با مبلغ کم.
2. تست موبایل در مرورگر کیف پول (Rabby / Trust / MetaMask).
3. اضافه شدن به Mini App به‌عنوان سرویس جدید؛ برای این‌که داخل تلگرام هم کیف وصل شود، اتصال WalletConnect لازم است.

## محدودیت‌ها
- خریدار باید یک‌بار بات را استارت کرده باشد (ربات نمی‌تواند اول پیام خصوصی بدهد). سایت قبل از پرداخت این را بررسی می‌کند؛ گیرنده فقط پیام را از خریدار می‌گیرد.
- KV رایگان روزی ۱۰۰۰ نوشتن دارد (هر هدیه ۴ تا)، یعنی حدود ۲۵۰ هدیه در روز.
